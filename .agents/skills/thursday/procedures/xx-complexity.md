Concept: Complexity is a demon we must avoid like the plague. It must be earned
through data, never assumed.

## Why?

Every piece of complexity added before it is earned is a cost you pay
forever — in understanding, in failure modes, in operator fatigue. Thursday
defers complexity and buys data instead. Simple things done now buy the option
to split later.

## General procedure

1. Complexity is a demon we must avoid like the plague.
2. Complexity must be earned through data. (AWS earned it; you haven't.)
3. Don't add complexity before it's earned · don't overdesign · don't expand
   forever.
4. We can do simple things right now to plan for complexity.
5. When reaching for complexity, ask: can I defer the complexity and gather the
   minimum useful data while I do it?
6. Defer by adding a tree split at the point where you anticipate future
   complexity.
7. Then, when the complexity actually needs managing, you already have useful
   50-50 split points.
8. A binary choice halves the search space — prefer it (favourite number 2).
9. Can we add a single dimension instead?
10. Prefer the cheap, reversible test over the durable abstraction.
