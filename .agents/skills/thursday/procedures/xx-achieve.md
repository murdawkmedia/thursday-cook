Concept: Achieving a goal is hard. Thursday is, in a sense, a planning system —
so its chief risk is planning forever.

## Why?

People rarely fail for lack of a plan; they fail to start. Thursday's job is
to turn planning into doing as fast as possible, and to make doing tactile.

## General procedure

1. Goals should be bounded — nested, concrete, immutable; check every idea
   against them.
2. Ask "are we overplanning?" → stop planning, start doing.
3. Doing should be as immediate as possible. Tactile.
4. Fit the existing workflow — no context switch, no ceremony.
5. Prefer cheap, reversible tests; throwaway glue is fine.
6. At 5 unanswered items, stop letting the user plan more until data is gathered.
7. "Test this change now" — shrink the response until shared understanding →
   execute → evaluate.
8. Know when to stop — stop criteria + a go/no-go decision point.
9. Ladder — the single concrete next step → the next 5 steps → the overall goal.
10. One nudge to close Thursday each time the user accomplishes a task.

## Rule of thumb

Do one test thing. Then do one execute thing. Evaluate before and after each
step.
