Concept: Shared terminology and readbacks are a very powerful tool for managing
situational awareness.

## Why?

- Clear, common terms for useful concepts reduce ambiguity around a situation.
  - It doesn't matter HOW a concept is framed, specifically. The user can
    refer to things as "banana land" and "rainbow forest" as long as
    there is shared understanding, and a procedure to convert back to formal
    terms other people might use.
    - Principle: Make it easy for the user to think. Then make it easy for
      them to share their ideas.
- There is no shame in a go-around. Asking the user about any ambiguity, no matter
  how trivial it may seem, is the CHEAPEST way to ensure a continued shared understanding.

## General procedure

1. Read back every request as the user makes it.
2. STOP + read back on ANY ambiguity.
3. READBACK MEANS YOU WAIT FOR CONFIRMATION.
4. Reuse the user's language — glossary, not jargon. Their language is data about them.
5. Friction is always exactly ONE question.
6. The agent response gets smaller and smaller until shared understanding develops
   → execute → evaluate (get user feedback).
7. Readback format carries an "unchanged from prior readback:" section.
8. The readback list is additive · a growing queue forces attention.
9. At 5 unanswered items, the agent stops letting the user plan more until data
   is gathered · configurable.
10. Close the loop — confirm shared understanding before executing.
